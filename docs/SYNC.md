# Synchronization and recovery

`syncFull` resumes an active baseline instead of discarding progress. A completed full request starts a fresh scan. `syncIncremental` uses native state, falling back to full for a new mailbox/configuration or expired history; `$since` never replaces historyId. Capture a profile anchor before listing, finish all pages, then replay history from the anchor. Continuation pages and pending message offsets are separate from the committed checkpoint. Commit only after durable event/write/dispatch completion.

All messages are listed without `labelIds` (which would impose AND); local filtering implements label OR and exclusion precedence. History deduplicates specific messagesAdded/messagesDeleted/labelsAdded/labelsRemoved entries and rereads their current state. Message 404 is proof for that scoped key; history 404 resets baseline. Configuration/project fingerprints reopen baseline when selection changes. A sync-only label mapping/hash detects renames and schedules a bounded baseline to refresh presentation without changing body/manifest decisions. Renames/read/flag changes update metadata with stable body/revision commitments.

Limits live at `connector-gmail.sync`: defaults 100 messages, 10 pages, 500 requests, 100 MiB HTTP bytes, 120 seconds and 32 MiB decoded body. `http` adds connection/read timeouts, response byte guards, finite attempts/jitter and Retry-After deferral. Responses/continuations are validated and redirects disabled. Continuation hashes are retained for the whole round, with an explicit finite 10,000-continuation guard; cyclic or overlong scans stop without confirming another checkpoint. Metrics omit content, subjects, addresses, credentials and cursor values.

A paused SyncResult reports errors plus `complete=false` audit state. Schedule the next run to resume. Listener/write/dispatch exceptions propagate rather than skipping failed items. Durable per-message/revision receipts reuse successful dispatches during page replay. The queue boundary is at-least-once if a worker dies between queue acceptance and its durable receipt; the host uses v1 revision/slot idempotency for triage. Generic hosts must implement equivalent ingestion idempotency.

Local pruning is disabled by default. When enabled, deletion/selection exits use only compound tenant+installation+provider+mailbox+message keys; baseline absence is acted on after baseline and catch-up complete. No Gmail delete/trash/modify request exists. Use a persistent shared cache and state disk. State/receipts require normal installation retention cleanup and remain separate from knowledge-document deletion.

Official references: [Gmail sync](https://developers.google.com/workspace/gmail/api/guides/sync), [history.list](https://developers.google.com/workspace/gmail/api/reference/rest/v1/users.history/list).
